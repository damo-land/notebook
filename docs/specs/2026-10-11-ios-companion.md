# iOS Companion

Status: in progress — T1–T5 done; T6 (chat) needs a device run
Source: The vault is only reachable from the Mac overlay. On the commute the
user wants to read notes, tick off tasks, and capture a thought from the phone.

## Goal

A native SwiftUI iPhone app that reads and writes the **same** vault the Mac
app uses — same folder, same file format — synced by iCloud Drive. No server,
no account, no second source of truth: the vault stays a folder of plain
markdown files, and either app can be deleted without losing anything.

## Decisions

- **Sync = plain iCloud Drive folder**, not an app-specific ubiquity container
  and not Supabase. The vault moves to `iCloud Drive/Stash`
  (`~/Library/Mobile Documents/com~apple~CloudDocs/Stash` on the Mac); the Mac
  app is re-pointed via Settings (existing `set_vault_dir` reindexes and
  re-watches — no Mac code change). The phone picks that folder once with the
  system folder picker and keeps a security-scoped bookmark. Needs no iCloud
  entitlement, no developer-portal container registration, and the folder stays
  visible in Finder and the Files app.
  Supabase rejected for v1: it needs a sync engine on the Mac side, auth, and
  turns one source of truth into two. Revisit only if Android or sharing appears.
- **SwiftUI, not Tauri mobile / React Native.** The Mac UI is a Spotlight
  overlay — almost nothing transfers to a phone layout, and iCloud file
  coordination is first-class only in native code.
- **No third-party Swift dependencies.** Markdown renders with Foundation's
  `AttributedString(markdown:)` (inline-only, whitespace preserved);
  `[[wiki-links]]` and bare URLs are rewritten into links first.
- **Format contract is a port, not a reimplementation.** `StashCore` (a local
  Swift package) ports `src/lib/vault/frontmatter.ts` and the id/create/update
  logic of `src/lib/vault/index.ts` byte-for-byte, checked against golden files
  generated by the TS library itself.

## Non-goals

On-device enrichment (stays Mac-only — a `/knowledge` note captured on the
phone is enriched when the Mac's watcher sees it). Chat was a non-goal here
until T6 (2026-10-11). Alerts/notifications
on the phone. Note deletion. Conflict resolution beyond what iCloud does (two
devices editing the same note → iCloud keeps a conflict version; capture always
creates a new uniquely named file, so this is near-zero in practice). iPad/Mac
Catalyst layouts. App Store distribution (personal device / TestFlight only).
Android.

## Riskiest assumption

That a security-scoped bookmark to an iCloud Drive folder gives reliable
offline access on iOS: files not yet downloaded appear as placeholders
(`.name.md.icloud`) or with a not-downloaded status, and must be explicitly
requested with `startDownloadingUbiquitousItem` before the commute. Simulator
iCloud is unreliable, so this can only be proven on the device.

Related traps:
- `timestampPrefix` (the file name / id) is **local** time, while `created` is
  `toISOString()` — **UTC with milliseconds**. Sample:
  `20261009-222436-…` vs `created: 2026-10-09T21:24:36.704Z`.
- Unknown frontmatter keys and non-`key: value` lines must round-trip verbatim,
  or a phone edit clobbers the `enriched:` / `alerted:` markers (see
  CONTEXT.md).
- On the Mac, iCloud "Optimize Mac Storage" can evict note files into
  placeholders the Rust indexer skips. Mitigation: Finder → right-click the
  `Stash` folder → **Keep Downloaded**.

## Layout

```
ios/

  StashCore/             Swift package: format, note model, task helpers, search, file I/O
    Tests/StashCoreTests/Fixtures/   golden files written by scripts/ios-format-fixtures.ts
  Stash/                 SwiftUI app target
```

## Tasks

### T1: StashCore — byte-compatible note format
- Status: done — 15 create / 18 round-trip / 5 update golden cases byte-identical; mutation check (UTC timestamps, Foundation whitespace) fails 14 cases; all 16 real vault notes round-trip unchanged.
- Acceptance criteria:
  - `parseNoteFile` / `serializeNoteFile` match the TS functions exactly:
    same `KEY_LINE` regex, same `KEY_ORDER`, booleans, inline lists, unknown
    keys and extra lines preserved, body bytes verbatim.
  - `createNote` produces the same id (local-time prefix + slug, `-2`/`-3`
    collision suffix) and the same file bytes as the TS `createNote` for the
    same inputs and clock; `updateNote` matches `setFrontmatter` /
    `replaceBody` semantics.
  - Golden files generated by `scripts/ios-format-fixtures.ts` (TS library)
    are re-produced byte-for-byte by Swift, and every golden file survives a
    parse → serialize round-trip unchanged.
  - Task helpers mirror `src/lib/task-list.ts` (open = `done != true`;
    deadline ascending, no-deadline last, then `created`).
  - `swift test` in `ios/StashCore` passes.

### T2: Vault access on device
- Status: code done, device-unverified — `VaultFiles` lives in StashCore and is tested against temp dirs (placeholders, Mac temp files, marker-preserving read-modify-write, no-overwrite create). Real iCloud download behaviour needs the phone.
- Acceptance criteria:
  - Folder picked once; bookmark persisted and re-resolved on launch (stale
    bookmarks refreshed).
  - Listing handles both real `.md` names and `.name.md.icloud` placeholders,
    and requests download of every not-yet-local note ("offline ready" count
    visible in Settings).
  - Reads and writes go through `NSFileCoordinator`; writes are atomic.
  - Refresh on app foreground and pull-to-refresh.

### T3: SwiftUI app
- Status: done in simulator (sample vault, screenshots of every screen); not yet run on a device.
- Acceptance criteria:
  - Tasks tab (home): open tasks, deadline-sorted, category filter, tap the
    circle to complete (writes `done: true`), undo available.
  - Notes tab: every note newest first, search over title/body/tags.
  - Note view: rendered body (inline markdown, tappable URLs and
    `[[wiki-links]]`), kind/tags/deadline shown, edit body in place.
  - Capture: one sheet, kind = note / task / knowledge, optional deadline and
    category for tasks. File lands in the vault with the Mac's format.
  - Builds for the iOS simulator with `xcodebuild`; runs against a local
    sample vault in the simulator.

### T4: Move the vault to iCloud Drive
- Status: done on the Mac (2026-10-11) — 16 notes copied to `iCloud Drive/Stash`, checksums identical, config re-pointed, index rebuilt; `~/Notebook` kept as backup. Keep Downloaded and phone pick still to do.
- Acceptance criteria:
  - The user copies `~/Notebook` into `iCloud Drive/Stash`, re-points the Mac
    app via Settings, marks the folder Keep Downloaded, and picks it on the
    phone. Documented in `ios/README.md`.

### T5: Sections, live refresh, neutral chrome (user feedback)
- Status: done in simulator — watcher picked up a Mac-side new note in <1.5s, poll picked up an in-place edit in <17s; light + dark screenshots. The system nav bar is hidden on the three list screens (its iOS 26 glass buttons left no room for the switch); a typographic section title + floating capture button replaced it after user feedback.
- Acceptance criteria:
  - No tab bar and no segmented control (HIG: no segmented controls in
    toolbars for switching context): the section names are one large title,
    current solid / others dimmed, tap to switch; a slim top row holds the
    rare actions (chat, ⋯ filters + settings); one floating glass + (thumb
    zone) captures into the current section. Single navigation stack, so a
    note pushes over everything. Search at the top, scoped to the section.
  - Completed tasks reachable ("Show completed" in the Tasks menu; tap to
    reopen).
  - Notes refresh while the app is in front: folder watcher (renames, i.e.
    the Mac's atomic writes) + 15s poll for in-place edits (3s while
    downloading); no rescan while the phone's own write is in flight.
  - Chrome uses the Mac's neutral text colour; amber only on task markers;
    links underlined.

### T6: On-device chat (Apple Foundation Models)
- Status: UI done and screenshot-verified with `-fakeChat`; the unavailable path shows correctly in the simulator. **The Foundation Models path is unverified** — it only compiles here; it needs the phone.
- Acceptance criteria:
  - Sparkle button (iOS 26+) opens a full-screen chat over the vault;
    transcript kept for the session; "New" resets.
  - Model tools: search notes, read a note, list open tasks — pure output
    builders in StashCore with tests; outputs capped so a turn fits the
    on-device context window.
  - Unavailable model (ineligible device, Apple Intelligence off, model
    downloading) shows the reason instead of the chat.
  - Context overflow starts a fresh session and retries once; guardrail and
    other generation errors show as a message, never a crash.
  - Cited `[[note-id]]`s are tappable and open the note.
  - Debug `-fakeChat` responder makes the UI testable in the simulator (the
    host Mac runs macOS 15, where the model can't run).

### T7: Monochrome design pass (user feedback)
- Status: done in simulator — all 15 key views screenshotted light + dark before and after.
- Acceptance criteria:
  - Black and white only, except the capture + (solid #2337FF, the one
    strong accent) and the page background (off-white
    #F7F7F5 / charcoal #141414). Greys are ink at opacity. Urgency (overdue,
    due today) is weight, not colour. Palette lives in `Theme` (Components.swift).
  - No row chevrons; one meta line per row ("Overdue · Yesterday · #work").
  - Note detail: first line is the heading, meta line under it, body with
    line spacing; no duplicate title in the nav bar.
  - Capture is a composer (kind chips, large field, due/category chips), not
    a grouped form; Settings explanations are section footers.

### T8: Home-screen widget
- Status: built; simulator-verified except what only a home screen or device can show (see below).
- Decisions: the widget never opens the vault (folder access belongs to the
  app); the app publishes a small JSON snapshot of open tasks to the App
  Group (`group.land.damo.stash`) after every scan or change and reloads
  timelines only when it changed. Per-widget settings: order (due first —
  default — or newest) and one optional category. Taps: anywhere →
  `stash://tasks`; + → `stash://new?kind=task` (a link on medium/large; on
  small an `openAppWhenRun` intent that leaves the route in the App Group,
  since small widgets allow one link). Background app refresh rescans so Mac
  edits reach the widget — iOS decides when.
- Verified here: snapshot model + day-label rollover (`swift test`); App
  Group container + snapshot written on launch; both routes (`-openURL`) and
  the intent's App Group round-trip; all three sizes light/dark (`-screen
  widgets`); no colour except the + across every screen.
- Not verifiable here: the widget on a real home screen, the small widget's
  + end to end, background refresh firing, App Group provisioning on device.
